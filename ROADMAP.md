# Aleuet: дорожная карта

Рабочий документ для стабильного прогресса. Каждая сессия разработки:
1. берёт **первую незакрытую задачу** из «Сейчас» (или ту, что назвал Еркебулан);
2. делает её небольшим законченным шагом: код, `pnpm lint`, `pnpm build`, проверка в браузере, коммит;
3. отмечает задачу здесь и добавляет строку в «Журнал».

Фазы по ТЗ v2: P0 прототип → **P1 технический MVP** → P2 удержание → P3 монетизация → P4 сообщество.

## Текущая фаза: P1 — один полный цикл с реальными пользователями

Цель (ТЗ, раздел 18): лекция по ссылке → просмотр с сохранением позиции → тест → XP и статус →
рекомендация → заявка. Схема и статус: [docs/architecture.md §6](docs/architecture.md).

### Сейчас (по порядку)

- [ ] **Заявки сохраняются.** Коллекция `leads` (продукт/событие/пилот): форма `ProductOrderForm` и `EventRegistrationModal` пишут в Firestore, правило «create для всех, read только admin», список заявок в `/admin`. Нужно для набора пилотной группы.
- [ ] **Реальное видео.** Заменить `VideoPlayerMock` на встраиваемый плеер (YouTube unlisted или другой хостинг — решить), поле `video.url` в Material и в админке.
- [ ] **Прогресс пользователя.** `users/{uid}/progress/{materialSlug}`: статус, позиция просмотра, результат теста. Правила + запись из плеера и теста.
- [ ] **XP один раз за действие.** Журнал `users/{uid}/xp/{eventId}` с идемпотентным id; профиль и `/learning` считают из него вместо `data/user.ts`.
- [ ] **Тесты из Firestore.** Коллекция `assessments` + редактирование в админке.
- [ ] **UTM и аналитика.** Сохранять `utm_*` при входе на страницу, базовые события (просмотр, тест, заявка) — выбрать инструмент.
- [ ] **Гостевой режим → аккаунт.** Прогресс гостя в localStorage, перенос при регистрации.

### Потом (P1, второстепенное)

- [ ] Topics и products в Firestore + админка.

### Не делаем до подтверждения пилотом

Платежи и подписки, лента коротких видео, соцфункции и рейтинги, AI-наставник, нативные приложения.

## Контент (параллельный трек)

Контент живёт в Firestore (`materials`, `events`), редактируется в `/admin`, публикуется сменой статуса
на `published`. Статические `src/data/*.ts` — демо и fallback, новые настоящие материалы туда не добавлять.

Чеклист одного материала:
- [ ] тема (`topicId`) и уровень, slug латиницей;
- [ ] название, подзаголовок, краткое описание на kk (+ ru/en по возможности);
- [ ] 3–5 результатов обучения (`learningOutcomes`);
- [ ] видео загружено, есть ссылка и главы с таймкодами;
- [ ] тест 3–5 вопросов с объяснениями;
- [ ] ресурсы (PDF, шаблоны, чеклисты);
- [ ] следующий материал / связанный продукт или событие;
- [ ] 2–3 коротких ролика для соцсетей со ссылкой на этот материал.

Пока нет поля под видео и тестов в Firestore (см. задачи выше), их можно готовить в документах заранее.
